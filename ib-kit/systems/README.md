# Systems — The Impact Engine Layer

A workflow runs once and finishes. A system runs continuously, keeps state between runs, and improves because it remembers what happened last time. Each system assembles workflows, agents and skills into a standing operating model with its own datasets, cadence and measures.

| System | Purpose | Standing state |
|---|---|---|
| [Origination](origination-system.md) | Source, prioritise and qualify opportunities | Universe · pipeline · trigger monitor · anti-target log |
| [Execution](execution-system.md) | Run deals, manage diligence, deliver materials | Model register · findings register · issues log · conditions register · source log |
| [Client Delivery](client-delivery-system.md) | Deliver high-impact materials and track performance | Materials register · source log · KPI definitions · synergy tracker · underwriting cases |

Each system can be adopted on its own. Adopting all three gives one continuous chain from a trigger event to a post-investment review.
